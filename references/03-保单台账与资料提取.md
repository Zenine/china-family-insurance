# 03 保单台账与资料提取

结论：每份保单一个台账文件，字段从保单原件里逐项摘录，原件里找不到的字段写「待补」，不凭产品宣传或记忆补数。

## 文件与命名

- 位置：`policies/<代号>/<险种>-<公司简称>-<年份>.md`，代号是被保人的代号。例：`policies/spouse/medical-shilijiankang-2023.md`。
- 险种用英文短词：`life`（寿险）、`critical`（重疾）、`medical`（医疗）、`cancer-medical`（防癌医疗）、`accident`（意外）、`annuity`（年金）、`group`（单位团险）、`property`（财产）。
- 公司简称用拼音；年份取首次投保年份。同一人同险种同公司同年份有两份时加后缀 `-2`。
- 文件名以 `_` 开头的（如 `_template.md`）不计入总览页。
- 原件与台账同名。库只存本机或私有仓库时放同目录，如 `policies/self/life-shilirenshou-2024.pdf`；库可能公开或同步到别处时放 `.private/policies/<代号>/`（示例家庭就是这样）。台账「关联资料」写实际路径。

## 字段

模板见 `templates/policy.md`，字段行写成 `- 字段：值`。总览页的加密明细读取下面九个字段，必须保留原字段名：

| 字段 | 写法 |
| --- | --- |
| 保单号（脱敏） | `末 4 位 1234`，只写末 4 位 |
| 保险公司 | 保单上的承保公司全称或通用简称 |
| 客服电话 | 保险公司官方客服电话 |
| 产品全称 | 保单首页上的产品名，不用销售平台的营销名 |
| 险种分类 | 寿险 / 重疾 / 医疗 / 意外 / 年金 / 财产 / 其他 |
| 保障期限 | 写清续保条件，如「1 年（保证续保 20 年）」「1 年（不保证续保）」「至 70 岁」 |
| 年保费 | 年交金额；月交写「月额 × 12 期」并在缴费方式写月交 |
| 续保或调整建议 | 一两句结论 |
| 覆盖充分 / 一般 / 不足 | 这份保单单独看的评价，矩阵档位以 `analysis/gap_matrix.md` 为准 |

其余字段（保额、等待期、免赔额、主要责任、除外责任、缴费期、生效日、受益人）同样摘录，缺口打分要用。

## 从原件提取

用户给 PDF、截图或口述时，按资料类型找字段：

| 资料 | 找什么 |
| --- | --- |
| 保险单 / 电子保单首页 | 保单号末 4 位、产品全称、承保公司、投保人、被保人、受益人、生效日、保险期间、保费、缴费方式 |
| 保障责任页 / 保障计划表 | 各项责任与保额、免赔额、赔付比例、等待期 |
| 特别约定 | 除外责任、加费、限额——核保结果都写在这里，必须摘录 |
| 条款 | 续保条件（是否保证续保、保证几年）、除外责任、犹豫期、退保规则 |
| 缴费记录 / 支付平台订单 | 实付金额、扣费方式（自动续保、月交、绑定的卡） |
| 单位团险服务手册 | 被保人范围、保额、报销范围（是否限社保内）、离职后是否失效 |
| 惠民保参保凭证 | 年度、保费、既往症是否可赔、起付线 |

规则：

1. **原件优先**：字段以保单原件为准；销售平台测评、宣传页只能当线索，与原件不符时以原件为准并在台账写原件的值。
2. **提取不到写「待补」**：截图没拍到、PDF 没有该页、口述说不清的字段，一律写「待补」，同时在 TODO 加一条「补 <代号> <险种> 保单的 <字段>」，写明去哪里补（保司 App、支付平台保单页、单位人事、学校）。
3. **金额与日期照抄**：保费、保额、日期按原件照抄，不四舍五入，不换算。
4. **一张截图可能缺页**：手机截图通常只有首页，等待期、免赔额、续保条件多在责任页和条款里，要请用户补拍或下载电子保单。
5. **不写敏感原值**：证件号、完整保单号、银行卡号、手机号不进台账；需要时看原件。
6. **读不了原件就直说**：PDF 或图片打不开、看不清、当前工具读不了图时，告诉用户读不了，请用户粘贴文字或口述上面「字段」一节列的字段，其余写「待补」，不猜。
7. **扫描件文字识别后核对一遍**：识别出的数字（尤其保额、保费、日期）与图片逐个对照，识别错一位就是错的台账。

刚收到的新保单，录台账时按 `templates/new-policy-check.md`（库里是 `新保单五查.md`）把健康告知、免责条款、等待期、续保条件、理赔流程五项查一遍，结果写进对应字段；犹豫期内要做的其他核对见 `references/20-投保后操作.md`。

## 在保状态对账

台账录完不等于在保。首次建库和每年复盘各做一次：

1. 请用户登录常用的保单入口——保险公司 App 或公众号、支付平台的保险页、单位人事——导出或截图「在保保单」清单。
2. 与 `policies/` 双向核对：清单有、台账没有的是漏记（常见：信用卡赠险、单位补充保险、学校统一投保、村集体或社区统一投保）；台账有、清单没有的可能已失效。
3. 月交和自动续保的保单确认扣费方式与扣费日：绑定的卡过期或余额不足会静默断保。能改年交的在到期换新时改年交；不能改的把扣费日写进成员档案「年度提醒」。

## 示例

示例家庭爸爸的定寿 `examples/demo-family/policies/self/life-shilirenshou-2024.md`：保单号只写「末 4 位 0001」；年保费写「3,600 元（高血压 2 级加费 50%）」——加费来自特别约定，照抄进台账；关联资料写 `.private/policies/self/life-shilirenshou-2024.pdf`。

爸爸的单位团险 `examples/demo-family/policies/self/group-shilirenshou-2026.md`：保障期限写「1 年（随单位每年续保，离职即失效）」，年保费写「单位承担」，减保退保写「离职当月起失效，不可转个人续保」——这些来自单位服务手册，缺口矩阵据此把爸爸意外判为「一般」。

爸爸的重疾 `examples/demo-family/policies/self/critical-shilirenshou-2023.md`：特别约定写着甲状腺疾病及其并发症不赔，照抄进「主要除外责任」。

哥哥的学平险由学校统一投保，保单在学校，没有原件可摘，所以不建台账，矩阵意外格写「缺资料」，`examples/demo-family/TODO.md` 列「向学校取得哥哥学平险保单」，写明为什么要（已满 10 周岁，身故保险金合计不超过 50 万）和怎么验证。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 用营销名当产品全称 | 照保单首页写，营销名可写在备注 |
| 截图里没有的字段按常见产品估 | 写「待补」，TODO 列补资料 |
| 漏掉特别约定里的除外或加费 | 特别约定逐条摘录 |
| 保障期限只写「1 年」 | 写清是否保证续保、保证几年 |
| 保单号写前几位加星号再写末位 | 只写末 4 位 |
| 录完台账就当在保 | 首次建库和每年复盘各对账一次 |
