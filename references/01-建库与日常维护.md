# 01 建库与日常维护

结论：家庭保险库是一个私有目录，用 `node scripts/init-library.mjs <库目录>` 一次建好骨架，之后每次资料变化都按「台账 → 矩阵 → 待办 → 变更记录 → 总览页」的固定顺序更新。

## 建库

1. 和用户确认库放在哪里。只能是本机目录或私有 Git 仓库，不放网盘公开链接、不放公开仓库。
2. 确认家庭成员代号。代号用英文小写：`self`（用户本人）、`spouse`、`daughter`、`son`、`father`、`mother`；同类成员多于一人时加序号，如 `daughter2`。
3. 在本 skill 目录（SKILL.md 所在目录）下运行：

   ```
   node scripts/init-library.mjs <库目录> --members self,spouse,daughter,son,father,mother
   ```

   不带 `--members` 时只建 `self`、`spouse`。脚本只新建缺失的文件，已有文件一律跳过；唯一会改的是已有 `.gitignore` 缺 `.private/` 时追加这一行。
4. 生成的结构：

   ```
   <库目录>/
   ├── AGENTS.md                 库规则，首行写明本库必须私有，含 skill 名称与版本
   ├── members/<代号>.md          成员档案
   ├── policies/<代号>/           保单台账，每份保单一个 .md
   ├── policies/_template.md      台账模板
   ├── analysis/gap_matrix.md     缺口矩阵（初始全部为「缺资料」）
   ├── analysis/_review-template.md  年度复盘模板
   ├── recommendations/_template.md  配置建议模板
   ├── 资料收集清单.md
   ├── 新保单五查.md              收到新保单时逐项核对的清单
   ├── 决策记录.md                本人裁决，每条一行
   ├── TODO.md
   ├── CHANGELOG.md
   ├── .private/                  口令、明细 JSON，以及不随库提交的原件；权限 700，已被 git 忽略
   └── .gitignore
   ```

5. 库是 Git 仓库时，先确认 `.private/` 被忽略：在库目录运行 `git check-ignore -v .private/x`，有输出才算忽略成功。`build-dashboard` 也会做同样检查，不通过就拒绝生成。
6. 按 `references/16-资料收集与问诊.md` 收资料，填成员档案（`references/02-成员档案.md`）和保单台账（`references/03-保单台账与资料提取.md`），再出缺口矩阵（`references/04-缺口矩阵.md`）。

库里的模板分别来自 `templates/`：`templates/library-AGENTS.md`、`templates/member.md`、`templates/policy.md`、`templates/gap_matrix.md`、`templates/review.md`、`templates/recommendation.md`、`templates/intake-checklist.md`、`templates/new-policy-check.md`、`templates/decisions.md`、`templates/TODO.md`、`templates/CHANGELOG.md`。

## 每次更新的固定顺序

任何一次资料变化（新投保、续保、体检、家庭变化、核保结果）都按这个顺序走完，不跳步：

1. **台账**：改 `members/<代号>.md` 或新建 / 修改 `policies/<代号>/*.md`。
2. **矩阵**：重算受影响成员的档位，改 `analysis/gap_matrix.md`。矩阵始终是当前状态，总览页读的就是它。
3. **待办**：完成的待办从 `TODO.md` 删掉；新出现的缺口或待补资料加进去。
4. **变更记录**：`CHANGELOG.md` 加一行。
5. **总览页**：`node scripts/build-dashboard.mjs <库目录>` 重建 `site/index.html`（见 `references/15-总览页与加密.md`）。

只改了台账没重建总览页，页面就会和台账对不上；明文总览和加密明细由同一次构建生成，不分开改。总览页只读成员档案、台账和矩阵，只改推荐方案时不必重建。

## 待办与变更记录的写法

**TODO.md**

- 每条写四件事：做什么、为什么（一句）、下一步、怎么验证完成。
- 按紧迫程度分段：错过不可逆的硬期限（满周岁费率窗口、投保年龄上限、续保截止）放最前；其次是决策与投保动作；再次是资料补录（按成员列）；最后是可选事项。
- 完成即删，不留勾选标记；完成事实写进 CHANGELOG。
- 用户已经拍板的口径（例如「某项口头提及、无医嘱的情况不作为告知项」）记进 `决策记录.md`（日期、裁决、理由、影响的规则），以后不再反复问。旧库写在 TODO 顶部「已定口径」里的，照样算数。
- 不写完整保单号、证件号、车牌、病史化验数值。
- 每年固定发生的事（续保月、居民医保缴费月、惠民保参保期）放在 TODO 末尾的「年度提醒」小节。

**CHANGELOG.md**

- 每条一行：`- YYYY-MM-DD 动作 + 对象 + 文件`，不写理由、不写未做的事。
- 同一天的多条不互相矛盾；后面订正了前面，就改成一条。

## 文档写法

库内所有 markdown 只记事实与规则：不写过程自证（「已核对」「已回读一致」）、不写防御性声明、不写被推翻的中间经过。用户原话、原件转录保持原样。推荐只到险种与保额层。

## 已有库接入

用户已经有一个自己维护的保险库（目录结构相近、字段不同），按下面步骤接入，不重建：

1. **先备份**：库是 Git 仓库就确认工作区干净；不是就整目录复制一份。
2. **补骨架**：对已有库直接运行 `node scripts/init-library.mjs <库目录> --members <已有代号>`。已有文件不会被改，只补缺的 `AGENTS.md`、模板、`.private/`、`.gitignore` 规则。已有 `AGENTS.md` 时脚本会跳过它，手工在其中加两行：

   ```
   - skill: china-family-insurance
   - version: <当前 skill 版本>
   ```

   并把首行改成「本库必须为私有仓库或仅本地保存」。
3. **对齐成员档案字段**：总览页按行首 `- 字段：值` 读取。每个 `members/<代号>.md` 至少要有 `- 代号 / 称呼：` 与以「家庭角色」开头的字段；原来分成「代号」「称呼」两行的，合并为一行 `- 代号 / 称呼：爸爸`。
4. **对齐保单台账字段**：总览页明细读取 `产品全称`、`保险公司`、`客服电话`、`险种分类`、`保障期限`、`年保费`、`主险保额`、`生效日 / 下次交费日`、`保单号（脱敏）`、`续保或调整建议`、`覆盖充分 / 一般 / 不足` 十一个字段。缺的补上，读不到的会显示「待补」。保单号字段改成 `末 4 位 1234` 的写法，删掉前缀加星号的旧写法（前缀和末位拼起来可能还原完整号码）。
5. **对齐缺口矩阵**：表头第一列含「成员」，后五列含「寿险 / 重疾 / 医疗 / 意外 / 年金」；每行第一个词是成员代号；每格以档位词开头（`充分 / 一般 / 不足 / 缺资料 / 不适用 / 核保受限`），说明放在括号里。原来写成「一般（核保受限：…）」的格子，按 `references/04-缺口矩阵.md` 重新判断是「核保受限」还是按已有保额打档。
6. **原件归位**：库只存本机或私有仓库时，保单 PDF、截图、体检报告可以留在 `policies/<代号>/`、`members/<代号>/` 随库提交；库可能公开、或会同步到网盘等其他地方时，原件移到 `.private/`。两种情况台账里都只留文件名；文件名里有真实姓名的改成「代号 + 类型 + 日期」（见 `references/14-隐私分级与资料原件.md`）。
7. **换掉旧总览页**：用 `node scripts/build-dashboard.mjs <库目录>` 生成 `site/index.html`；旧的手写总览页与旧加密脚本在新页面能正常解锁后删除。旧页面曾部署到外网的，按 `references/15-总览页与加密.md` 重新评估部署方式，并更换口令。
8. **撤掉旧规则副本**：库里原来放着的旧版方法说明、旧版 skill 副本删掉，以本 skill 为准，避免两套口径。
9. **验收**：运行 `node scripts/privacy-scan.mjs <库目录>/members <库目录>/policies <库目录>/analysis`，命中的证件号、手机号、完整保单号逐条改掉；重建总览页并用口令解锁一次，核对每位成员的档位与矩阵一致；CHANGELOG 记一行「接入 china-family-insurance <版本>」。

## 升级到 0.2

0.1 建的库按下面步骤升级，不重建：

1. **先备份**：库是 Git 仓库就确认工作区干净；不是就整目录复制一份。
2. **补新文件**：运行 `node scripts/init-library.mjs <库目录> --members <已有代号>`。已有文件一律跳过，只补 `新保单五查.md`、`决策记录.md` 等缺的文件；`policies/_template.md`、`recommendations/_template.md` 已存在时不会更新，分别用 `templates/policy.md`、`templates/recommendation.md` 覆盖（这两个模板文件里没有用户数据，用户改过的先问一次）。
3. **改版本号**：`AGENTS.md` 里的 `- version:` 改成 `scripts/lib/version.mjs` 里的版本号。
4. **台账补新字段**：每份 `policies/<代号>/*.md` 按 `templates/policy.md` 补 `保障到期日`、`身故保额`、`宽限期`、`报案时限`、`理赔材料（摘要）`、`理赔渠道` 六个字段。合同在手、条款里写了的照写；条款里找不到的写「未识别」；还没拿到合同的写「待补」。
5. **汇总已有裁决**：把 TODO 顶部「已定口径」、CHANGELOG 和 `recommendations/` 里标明「本人裁决」的条目，逐条抄进 `决策记录.md`（日期、裁决、理由、影响的规则），原处保留。
6. **重建总览页**：`node scripts/build-dashboard.mjs <库目录>`。还没补新字段的台账，明细里显示「待补」；写「待补」「未识别」的照原样显示。解析不出日期的项不进「近 60 天待办」，构建不报错；写了内容却读不出下次交费日（「/」右侧不是 `YYYY-MM-DD`）或宽限期天数的，终端打印警告，按警告改台账，确实不知道的改写「待补」或「未识别」。
7. **记一行**：CHANGELOG 写「升级到 china-family-insurance <版本>」；补字段时新发现的缺口按固定顺序更新矩阵和 TODO。

## 示例

示例家庭在 `examples/demo-family/`：六位成员（爸爸、妈妈、哥哥、妹妹、外公、外婆），12 份保单。建库命令：

```
node scripts/init-library.mjs <库目录> --members self,spouse,daughter,son,father,mother
```

妹妹的居民医保参保生效后，按固定顺序更新：在 `members/daughter.md` 把医保改为已生效 → 投少儿医疗后新建 `policies/daughter/medical-<公司简称>-<年份>.md` → 矩阵妹妹医疗由「缺资料」改为按新保单打档 → 删掉 TODO 里「妹妹居民医保生效后投少儿医疗」→ CHANGELOG 记一行 → 重建总览页。示例的待办写法见 `examples/demo-family/TODO.md`，变更记录见 `examples/demo-family/CHANGELOG.md`。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 把库建在公开仓库或同步盘公开文件夹 | 只放本机或私有仓库，`AGENTS.md` 首行写明 |
| 改了台账不改矩阵、不重建总览页 | 每次按固定五步走完 |
| 待办完成后打勾保留 | 完成即删，CHANGELOG 记一行 |
| 已拍板的事反复问用户 | 记进 `决策记录.md`，下次先读 |
| 已有库直接重建、覆盖用户原有内容 | 用 init-library 补骨架，字段逐项对齐 |
| 接入后旧总览页、旧规则副本还留着 | 新页面验收通过后删除旧的 |
