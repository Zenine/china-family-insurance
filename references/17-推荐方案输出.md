# 17 推荐方案输出

结论：推荐方案推到险种与保额层——每人补什么险种、保额、保障期、交费期、年预算区间、优先级、核保策略和挑选要点，写进 `recommendations/YYYY-MM-DD.md`（模板 `templates/recommendation.md`）；默认不点名产品，用户主动要产品时，由用户自己的 AI 按本章方法当场联网查，写明查询日期与来源。

## 判断顺序

出方案前先确认缺口矩阵是最新的（`references/04-缺口矩阵.md`），然后按这个顺序逐人逐险种推：

1. **读输入**：`analysis/gap_matrix.md`、全部成员档案、`TODO.md`（含顶部「已定口径」和未录入保单）、上一份 `recommendations/`。用户拍过板的不重议。
2. **定谁需要什么**：矩阵里「不足」「一般」「核保受限」的格子是候选；「缺资料」先补资料，方案里写「先补资料」，不给保额；「不适用」不配。
3. **定保额**：
   - 寿险：应保额 − 现有保额，公式见 `references/04-缺口矩阵.md`。
   - 重疾：补到每人 50 万；成人可按 3–5 年家庭开销上调。
   - 医疗：百万医疗或长期医疗，看保证续保年限，不比保额；核保受限的写防癌医疗（`references/11-医疗险与重疾险.md`）。
   - 意外：成人身故保额 ≈ 1 年家庭开销且含意外医疗；未成年人身故保险金合计不超过监管上限（不满 10 周岁 20 万；已满 10 周岁未满 18 周岁 50 万），与学平险等已有保单合计计算。
   - 年金 / 教育金：有目标金额与年份才算，没有就写「不配置」或「先补资料」。
4. **定保障期与交费期**：定期寿险覆盖到房贷还清和最小孩子 22 岁；重疾成人至 70 岁或终身、孩子保到能自主投保（`references/10-定期与终身.md`）；长期险交费期拉长到 20 年或交至 60 岁，保费杠杆更高；医疗、意外为 1 年。
5. **定年预算区间**：写量级区间。有当年投保页试算或测评价格的，按查到的写并在文末注明来源与日期；查不到写「待试算」，不编数字。
6. **定优先级**：高 / 中 / 低，按 `references/05-配置原则.md`：支柱 → 孩子 → 老人；同层里硬期限、无健康告知、保费低、越晚越难核保的先。
7. **定核保策略**：健康正常的写「直接智能核保」；有异常的写要带哪些资料、几家并行、接受哪些加费或除外、被拒后的替代路径与重试条件（`references/06-核保策略.md`、`references/07-慢病与核保受限人群.md`）。有窗口的写硬线与计划投保日（`references/08-少儿投保窗口.md`）；孩子长期险写豁免加不加（`references/09-投保人豁免.md`）。
8. **写挑选要点**：这个人挑产品时最该看的 2–3 条条款，见下文「条款筛选清单」，结合他的健康与职业写具体。
9. **算预算合计**：现有年保费 + 新增区间，对比用户给的年保费预算和税后收入占比；超预算按 `references/05-配置原则.md` 的三档从后往前砍，并写明砍了什么。

写完后：每条要执行的动作进 `TODO.md`（做什么、为什么、下一步、验证），`CHANGELOG.md` 加一行，矩阵不因方案改动——投保落地后才改矩阵。

## 输出格式

照 `templates/recommendation.md`：

- **家庭概况**：成员与年龄、税后年收入与主要负债、年保费预算；寿险应保额的算式写出来。
- **每个成员一节**：五险种一张表（保额 / 保障期 / 交费期 / 年预算区间 / 优先级），表下两行「核保策略」「挑选要点」。不需要的险种写「不配置」，已有且够的写「维持」。
- **预算合计**：全家年保费、占税后年收入比例。

不写具体产品名、不写返佣或购买链接。

## 用户要具体产品时

用户明确说「推荐几款」「帮我找产品」时才做，由用户自己的 AI 当场联网查询当年在售产品。本 skill 不内置产品清单，产品每年都在变。

### 去哪里查

| 来源 | 查什么 |
| --- | --- |
| 保险公司官网、官方 App 或公众号 | 产品条款、费率表、投保页试算、健康告知原文 |
| 持牌保险经纪 / 代理平台（页面底部能看到经营许可证） | 同类产品比价、测评、智能核保入口 |
| 中国保险行业协会网站的产品信息披露 | 条款备案、产品是否在售 |
| 国家金融监督管理总局网站 | 保险公司与中介机构是否持牌 |

测评文章只当线索，保额、价格、健康告知以保险公司条款和投保页为准。

### 搜什么

搜索词由「年份 + 险种 + 年龄或人群 + 这个人的关键条件」组成，例如：

- `2026 定期寿险 42 岁 高血压 加费`
- `2026 防癌医疗 保证续保 不问高血压`
- `2026 少儿重疾 定期 30 年 0 岁`
- `2026 长期医疗 保证续保 20 年 家庭单`
- `2026 老年意外 骨折 65 岁`

每个险种至少找 3–5 款候选，再按下面的清单筛。

### 条款筛选清单

| 条款 | 看什么 |
| --- | --- |
| 保障期 | 是否覆盖方案要求的年限；定期寿险至几岁 |
| 保证续保 | 医疗险保证续保几年；一年期的停售风险 |
| 健康告知宽严 | 逐条对照成员档案，这个人能否全答「否」；不能的，是否支持智能核保、对他的病情给什么结论 |
| 免责条款 | 条数和内容；寿险看是否只有常见几条 |
| 等待期、免赔额 | 天数；免赔额是否家庭共用 |
| 职业类别 | 承保职业是否包含这个人的类别 |
| 投保年龄 | 是否还在可投年龄内；跨档时点 |
| 交费方式 | 能否年交；月交的断保风险 |
| 价格 | 投保页按这个人的年龄、保额、保障期、交费期试算 |

### 查询结果怎么写

在当期 `recommendations/YYYY-MM-DD.md` 末尾加一节「产品查询（YYYY-MM-DD）」，每款一行：产品名、保险公司、查询日期、来源页面地址（官网或原始页面，不用推广链接）、关键条款、试算价格、与这个成员情况冲突的地方。开头写一句：投保当天以保险公司投保页和条款为准。

产品名只出现在这一节和投保后的台账里，不进缺口矩阵和总览页明文。

### 不能联网时

把上面的「去哪里查」「搜什么」「条款筛选清单」原样交给用户，并按成员情况填好搜索词。用户查到后把产品页截图或条款发回来，AI 按清单逐条比对，写进「产品查询」一节，来源写「用户提供」加日期。

## 示例

示例家庭的完整方案见 `examples/demo-family/recommendations/2026-11-20.md`。以爸爸为例：

- 寿险：应保额 362 万，现有 200 万，再加 170–200 万（合计 370–400 万，不低于应保额，买后档位「充分」），保至 70 岁，优先级高。
- 医疗：被拒，写防癌医疗 200 万以上、血压控制满 1 年后重试百万医疗，优先级高。
- 核保策略：带近半年血压记录与体检报告，多家同时智能核保，接受加费；甲状腺结节接受除外。
- 挑选要点：寿险看健康告知对高血压的分级要求与加费比例；防癌医疗选不问高血压、保证续保的款。

如果用户接着说「爸爸的防癌医疗帮我找几款」，AI 联网搜 `2026 防癌医疗 保证续保 不问高血压`，筛出 3–5 款，按清单核对每款的健康告知是否问高血压、续保条件、等待期，写进「产品查询（2026-11-20）」并附来源。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 不出保额，只说「建议买重疾」 | 每格写保额、保障期、交费期、预算、优先级 |
| 缺资料的格子也给保额 | 写「先补资料」 |
| 编价格 | 查不到写「待试算」，查到的注明来源与日期 |
| 默认列出几款产品 | 用户主动要求才查 |
| 凭记忆说产品，不写查询日期 | 当场联网查，写日期与来源 |
| 给推广或返佣链接 | 只给官网或原始页面 |
| 方案写完就改矩阵 | 投保落地后才改矩阵 |
| 超预算不说砍了什么 | 按三档砍，写明砍掉的项 |
